# Yamaha XT600 3AJ Germany

Статический мобильный сайт: HTML/CSS/vanilla JS, Python, JSON, GitHub Actions и GitHub Pages. Никаких демонстрационных карточек. Контрольный URL сохранён в `config/search.json` и каждый раз проверяется заново.

## Локальный запуск

Python 3.12+:

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python scripts/build.py
python -m http.server 8000 --directory dist
```

Откройте http://localhost:8000. Сервер нужен для загрузки JSON; не открывайте HTML через file://.

## Обновление

```sh
python scripts/update_listings.py
python scripts/build.py
```

Для проверки только контрольного объявления и уже найденной истории: `python scripts/update_listings.py --seed-only`. Такой запуск явно отмечает поиск как неполный. Поисковые запросы и ограничение страниц находятся в `config/search.json`. Поиск охватывает всю Германию в категории мотоциклов, не требует 3AJ или Ténéré в заголовке. Просматриваются все найденные карточки, а не только совпадения по названию модели. Ограничение страниц или ошибка отражаются в `errors` и `run_status`.

`scripts/search.py` — сменный адаптер HTTP, поиска и парсинга. `scripts/verify.py` — обязательный допуск по визуальной проверке. `scripts/update_listings.py` — слияние истории и атомарная запись. `scripts/build.py` — сборка публичных файлов в dist.

## Данные и достоверность

`data/listings.json` хранит `listings`, `inactive_listings`, `candidates`, ошибки, время последней попытки и последней успешной проверки. Каждая запись содержит ID, название, цену, предыдущую цену, историю цен, город, регистрацию, пробег, дату публикации, точные ссылки, URL фото, SHA-256 фото, first_seen, last_seen, last_checked, active и результат визуального допуска.

HTTP 404/410 или подтверждённый редирект на категорию/список делают объявление inactive. Сетевые ошибки, блокировки и неизвестная разметка сохраняют последнюю известную запись; не объявляют её удалённой. Главная скрывает записи с ошибкой проверки, неподтверждённым фото, неактивные записи и записи старше 36 часов. Ошибка загрузки фото также убирает карточку. NEW действует 48 часов от first_seen; изменение цены сравнивается с предыдущей отличавшейся ценой.

Ссылка app-share состоит из фактически полученного URL того же ID и точного набора параметров из запроса пользователя. Slug, ad ID и location ID не генерируются. Контрольная ссылка полностью совпадает с предоставленной пользователем. Сама ссылка открывается обычным `<a href>`; поведение iOS зависит от системных настроек Universal Links.

Пробег переносится из поля продавца без интерпретации. У контрольного объявления в описании указана переборка двигателя при 60 000 км, хотя структурированное поле показывает 3 500 км; это не независимое подтверждение общего пробега.

## Визуальная проверка MVP

Новые кандидаты не публикуются автоматически. Откройте фотографии именно объявления из `candidates`, убедитесь в цельности мотоцикла, красно-белой расцветке и характерной компоновке 3AJ: передний обтекатель с двумя круглыми фарами, соответствующие бак, боковины и общая конструкция. Сравните несколько ракурсов с проверенным эталоном. Переделанные или неоднозначные мотоциклы отклоняйте. Название, год и текст продавца не являются доказательством поколения. Запчасти, доноры и wanted исключаются.

После фактического просмотра:

```sh
python scripts/review.py 'EXACT_LISTING_URL' --approve --evidence 'Конкретные признаки, замеченные на фотографиях'
python scripts/update_listings.py
python scripts/build.py
```

Решение сохраняется в `data/visual_reviews.json` и привязывается к точному объявлению, URL и хешу основной фотографии. Изменение фото снимает допуск. Для нового правила обновите `RULE_VERSION` в `verify.py` и перепроверьте записи. CLI — инструмент регистрации человеческого решения, не классификатор изображения.

Для полностью автоматического определения нужны: размеченные эталонные фото 3AJ и исключаемых 3TB/2KF/2NF/43F/1VJ/34L; анализ нескольких фото из каждой галереи; модель зрения с калиброванной уверенностью и обязательным отказом при неопределённости; тестовый набор похожих поколений, перекрасов и переделок; журнал доказательств и очередь ручного разбора. В MVP нет обученной модели или выдуманного AI-verification. Добавлять автоматический положительный допуск до оценки ложных срабатываний нельзя.

## GitHub Pages и ежедневное обновление

1. Создайте отдельный публичный GitHub-репозиторий и загрузите содержимое этой папки в ветку `main` (включая `.github`).
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Разрешите workflow запись в репозиторий (Settings → Actions → General → Workflow permissions). В защищённой ветке понадобится подходящее разрешение или отдельная ветка для данных.
4. Actions → **Daily check and GitHub Pages** → Run workflow. После успешного запуска URL появится в окружении `github-pages`.

Workflow `.github/workflows/daily-update.yml` проверяет объявления, сохраняет JSON в Git, собирает `dist`, загружает Pages artifact и публикует его в том же запуске. Это не зависит от того, запускает ли bot-коммит новый workflow. Два UTC-триггера и проверка Europe/Berlin выбирают 07:17 по местному времени зимой и летом. GitHub может задержать расписание; в неактивных публичных репозиториях расписание может быть отключено после 60 дней — проверьте Actions. Тесты: `python -m unittest discover -s tests -v`.

Sites-публикация — отдельный снимок, не обновляемый этим GitHub Pages workflow. Постоянный ежедневный мониторинг начинает работать только после настройки репозитория и первого успешного workflow. При блокировке Kleinanzeigen workflow сохраняет историю и отмечает неполноту; требуется сменный разрешённый источник/адаптер, а не обход защиты.

Документация: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
